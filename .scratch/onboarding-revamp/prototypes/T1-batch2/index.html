T1 · batch 2 · throwaway prototypes

Entry-arc visual directions — five new candidates

Auth → onboarding → plan reveal, as three screens per direction. Open any screen directly in a browser — no build step. Onboarding screens are interactive: pick an answer to advance, use Back to see the reverse transition. Nothing here touches apps/web.

Batch 1 was rejected in full. None of the five below reuse its signature devices: no console/HUD bezel, no large animated mascot, no notebook or hollow-outline numerals, no receipt ledger, and no full-bleed color-wash that changes per phase.

1 — Broadsheet

editorial · warm paper · serif

The entry arc as a newspaper printed for one reader. Masthead + folio chrome, hairline rules, Fraunces serif headlines; each onboarding question is an "article" with a kicker and a byline, options are a ruled index list (A, B, C…). Plan reveal is the front page: the calorie figure as the banner headline, macros as box-score columns, the breakdown as a methodology footnote. Stry survives only as a byline ("By Stry, wellness desk") — voice, not mascot.

Layout: single reading column; progress = folio "Page X of 8" + a hairline fill rule. Motion: article settles (rise 16px + fade, 200ms) on step change; fill-rule tweens. Opacity-only under reduced motion. Tokens: ink/lavender as-is; extends with paper #faf8f2 + Fraunces (called out in-file). vs. rejected batch: print-craft without the notebook's stationery devices — no hollow numerals, no margin lines, no receipt; serif editorial hierarchy instead of a mascot or color zones.

2 — Darkroom

dark-native · luminous · mono data

A darkened studio where only one thing is lit at a time. Near-black canvas using the existing .dark tokens verbatim, lavender as light (glowing focus borders, a light-line progress bar), JetBrains Mono for labels and data. The plan reveal is a spectrometer readout: one glowing number, a single spectral macro bar, a dotted-leader ledger. Stry is reduced to a 6px signal dot — ambience, not a character (frozen under reduced motion).

Layout: centered "chamber", fixed light-line progress across the top. Motion: chamber relights (fade + 10px rise, 250ms); glow pulses are ambient-only and disabled under reduced motion. Tokens: adopts the dark token palette natively; extends only with JetBrains Mono + glow shadows. vs. rejected batch: dark without the console — zero bezel, zero pixel art, zero mascot; minimal luminous-lab craft instead of a game frame.

3 — Wayfinding

transit signage · structured · playful

The arc as a metro line with named stations. A route line (You → Body → Goal → … → Plan) is the shared chrome on all three screens; each question is an ink gate-sign with a lavender "STOP 3 · GOAL" chip; answers are chunky line-pills. The reveal is the arrivals board: destination, big "departure-time" calories, macro rows with status chips. Stry is voice-only — the PA announcer ("‣ PA: …"), which also hands the OAuth redirect a natural metaphor ("transferring lines"). Colors are constant ink/lavender — explicitly not per-phase.

Layout: route-line progress with real progressbar semantics + aria-current on the current station. Motion: horizontal slide 24px + fade, 180ms — direction encodes advance vs. back (fits the travel metaphor). Opacity-only under reduced motion. Tokens: pure token palette; extends only with Archivo as the signage face. vs. rejected batch: wayfinding narrative without washing phases in color, without a mascot on screen, and without any bezel — signage panels, not a console.

4 — Soft Terrain

organic calm · warm paper · trail

Onboarding as a walk up a hill. Warm paper with faint topographic contours (a constant texture, not a phase tint), a ridge-line trail whose fill and cairn marker advance with each answer, rounded organic option pills. The reveal is the summit: the cairn planted at trail's end, macros as a layered "geology" bar, the breakdown as a trail log. Stry is reimagined as the cairn — a small, static, faceless trail marker (present, but nothing like the pixel elephant).

Layout: trail header (progress) + single white question card on contour paper. Motion: card rises 20px + fades, 220ms; cairn tween 250ms along the trail (jumps instantly under reduced motion). Tokens: text/border/lavender as-is; extends with warm paper #f7f4ee + contour line color. vs. rejected batch: organic/natural instead of digital HUD, notebook stationery, or color zones; mascot reimagined as an object in the world, not a character on a stage.

5 — Studio Deck

instrument · Swiss grid · spec sheet

The anti-mascot direction: Stride as a precision measuring instrument. A left meta rail carries the step fraction (03/08), a percent meter, a section index, and a time estimate; the main panel is a spec sheet — Space Grotesk questions, hover-invert option rows, dimension-line callouts. The reveal is the finished engineering sheet: measured calorie figure with tolerance, a ticked macro bar, and a signed-off calculation table. Stry is absent as a character; empathy survives only as small "NOTE —" annotations on sensitive steps.

Layout: persistent rail + spec panel; progress = fraction + meter + index with aria-current. Motion: tool-like snap — 150ms fade + 8px slide on the panel only. Opacity-only under reduced motion. Tokens: ink/lavender/borders as-is; extends with Space Grotesk/JetBrains Mono and near-square corners. vs. rejected batch: trades warmth for credibility — no mascot at all, no color washes, no stationery; a utilitarian counter-proposal so the range of this batch is genuinely wide.

Constraints every direction respects (R1 + R2)

  • One focused question per step — persona line is framing only, never a chat log.
  • Motion on the step card only: slide+fade, 150–250ms, translate ≤24px; persistent chrome (progress, header) never animates layout.
  • prefers-reduced-motion: everything collapses to a fast opacity crossfade; ambient loops (signal dot) freeze.
  • Focus moves to the step <h2 tabindex="-1"> on every change; a single polite live region is used for validation status only — never at the same time as the focus move.
  • Real progress semantics: role="progressbar" with aria-valuenow/min/max (+ aria-current="step" where a step list exists).
  • Validate-before-advance: Continue is inert until a selection; an invalid attempt announces via the live region (WCAG 4.1.3).
  • Auth and onboarding never share DOM (the <Show> boundary) — continuity is purely visual language: same chrome, same progress metaphor, same type system per direction.
